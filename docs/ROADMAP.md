# 로드맵

각 단계는 **완료 조건을 통과해야** 다음으로 간다. 조건은 전부 손으로
확인할 수 있다.

---

## P0 — 형식 확정 (1~2일)

MCP도 앱도 없다. 파일 형식이 쓸 만한지만 본다.

- `packages/core` : `types.ts`, `tokens.ts`, 경로 규칙, zod 검증
- `.lounge/` 를 손으로 만들고 `entries/*.md` 3~4개를 직접 작성
- `LOUNGE.md` 규약 본문 작성

**완료 조건**
- 요약(`about`) 한 줄만 보고 "열지 말지"가 판단되는가
- 같은 항목을 두 사람이 봐도 같은 결론이 나오는가

여기서 형식이 틀리면 뒤를 전부 뜯는다. 서두르지 않는다.

---

## P1 — 뷰어 (3~5일)

읽기 전용. 쓰기 코드를 넣지 않는다.

- Tauri 셸, 프로젝트 연결/목록
- `.lounge/` 파일 감시 → 재실 패널 + 타임라인
- 항목 상세 패널
- 라운지 없는 폴더 처리

**완료 조건**
- 손으로 파일을 고치면 1초 안에 화면이 바뀐다
- `sessions/` 를 손으로 만들면 재실 패널에 뜬다
- 2초 안에 "지금 누가 있고 볼 게 있나"가 읽힌다

---

## P2 — MCP 도구 (4~6일)

앱이 이미 보여주고 있는 그 파일을 에이전트가 만들게 한다.

- stdio 서버 뼈대, 라운지 탐색(위로 올라가기), actor 해석
- `join` `post` `open` `ack` `leave` `digest`
- 브리핑 계산 + 출력 상한
- stale, supersede 경고, 게으른 스윕

**완료 조건** — 아래 검수표 전부 통과

---

## P3 — 통합과 포장 (2~3일)

- `CLAUDE.md` / `AGENTS.md` / `hooks.json` / `skills/lounge`
- Claude Code, Codex 플러그인 매니페스트
- Claude Desktop `.mcpb` (경로 설정 포함)

**완료 조건**
- 세 클라이언트에서 같은 라운지에 들어가 항목을 주고받는다
- 설치가 config 한 줄로 끝난다
